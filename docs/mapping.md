# Карта импорта

Восстановлена по фотографиям. Поля ищутся по техническому заголовку, без привязки к букве столбца.

| Поле шаблона | Входное поле основной матрицы | Вычисляемый код |
| --- | --- | --- |
| CHANNEL_INDICATOR_DESCRIPTION | CHANNEL_INDICATOR_DESCRIPTION | CHANNEL_INDICATOR |
| SP_NAME_DESCRIPTION | SP_NAME_DESCRIPTION | SP_NAME |
| OPERATION_DESCRIPTION | OPERATION_DESCRIPTION | OPERATION_TYPE |
| RELATION_TYPE_DESCRIPTION | RELATION_TYPE_DESCRIPTION | RELATION_TYPE |
| SBOL_PRO_PLATFORM_DESCRIPTION | SBOL_PRO_PLATFORM_DESCRIPTION | SBOL_PRO_PLATFORM |
| TRANSACTION_TYPE_DESCRIPTION | TRANSACTION_TYPE_DESCRIPTION | TRANSACTION_TYPE |
| CLIENT_TYPE_DESCRIPTION | CLIENT_TYPE_DESCRIPTION | CLIENT_TYPE |
| INSPECTED_PERSON_DESCRIPTION | INSPECTED_PERSON_DESCRIPTION | INSPECTED_PERSON |
| STOP_LIST_STATUS_DESCRIPTION | STOP_LIST_STATUS_DESCRIPTION | STOP_LIST_STATUS |
| MATCH_NEGATIVE_CASE_DESCRIPTION | MATCH_NEGATIVE_CASE_DESCRIPTION | MATCH_NEGATIVE_CASE |
| VALUE | VALUE | DESCRIPTION, VALUE_PRIORITY, COMPLIANCE_DECISION |
| MAX_AMOUNT | MAX_AMOUNT | — |
| TITLE_FOR_CLIENT | TITLE_FOR_CLIENT | — |
| TEXT_FOR_CLIENT | TEXT_FOR_CLIENT | — |
| Поле Байпас | VALUE_SWITCH (настраивается) | DESCRIPTION_SWITCH |

Технический код, указанный в поле «описание», распознаётся по тому же справочнику и заменяется его русским описанием. Если целевой технический столбец содержит формулу, она остаётся. Если код хранится обычным значением, он обновляется вместе с описанием.

`DESCRIPTION` шаблона не копируется: на снимке там техническое решение вида `operationPermitted`, тогда как `DESCRIPTION` основной матрицы — русское описание решения, вычисляемое по `VALUE`.

Пустое значение в присутствующем поле шаблона означает очистку поля результата. Пустой MAX_AMOUNT отличается от числового нуля. Поле Байпас при «пропуск контролей» также очищается.

## Общие поля сверху

Если поле не заполнено в строке, используются значения сверху шаблона:

| Поле | Ячейки, в порядке приоритета |
| --- | --- |
| Канал | D3, B3 |
| Подсистема: описание / код | D4, B4 / D5, B5 |
| Операция: описание / код | D6, B6 / D7, B7 |
| Тип клиента | B8 |
| Участник: описание / код | B10 / D10 |

Значения строки имеют приоритет. Шапка читается только для тех пар «код/описание», которые отсутствуют в строке. Формульная D8 отдельно не читается: при заполнении из шапки код типа клиента определяется по B8 и справочнику основной матрицы. Ручная D8 используется как запасной код, если описание B8 отсутствует.

Простые ссылки в шаблоне раскрываются программой: `=B3`, `=$B$3`, `='Имя листа'!$B$3` и цепочки таких ссылок. Например, строка A18 может ссылаться на D3, а D3 — на B3. Кэш результатов формул не используется. Циклические ссылки и неизвестные вычисления в нужных полях вызывают ошибку; неизвестная формула в неиспользуемом поле шапки импорту не мешает.

Лист шаблона выбирается по фрагменту `ЗАПОЛНИТЬ`. Заголовки ищутся в первых 25 строках, данные — начиная со строки 18. Эти параметры задаются в config.json.

## Что требует локальной сверки

Составной ключ группы и RELATION_TYPE подтверждены. Внутренний ключ строки принят для прототипа: TRANSACTION_TYPE, INSPECTED_PERSON, STOP_LIST_STATUS, MATCH_NEGATIVE_CASE, MAX_AMOUNT. Разные стопкоды одной группы — разные записи. Реакция и тексты не участвуют в ключе. Нужно проверить, нет ли в реальной матрице дополнительных условий, различающих строки одной группы.

Старые дубли не исправляются. При нескольких совпадениях для полного ключа строка шаблона пропускается без обновления или добавления, а остальные строки обрабатываются. Неоднозначное соответствие в справочнике для строки шаблона также направляет её на ручной разбор. Если загруженные шаблоны задают разные значения для одного ключа, пропускаются все варианты этого ключа. Список пропусков содержит источник и причину; в браузере есть отдельный счётчик.

Неразобранные старые строки сравниваются по всем доступным полям ключа: известное несовпадение исключает пересечение, неизвестное значение не считается пустым или отсутствующим. Возможное пересечение означает ручной разбор соответствующей строки шаблона. Номер последней строки учитывает и неразобранные записи, поэтому новые строки добавляются после них.

Столбцы IFT/PROM и номер задачи не участвуют в импорте существующих строк. У новых строк они пустые по умолчанию.

Служебная область «Данные для БИПО» в импорт не включена: соответствия основной матрице для неё не заданы. Цвет строк не является командой удаления.

## Справочники и формулы

Секция `aliases` в config.json задаёт соответствия конкретного поля: например, `STOP_LIST_STATUS` / `Флаг 66` → `MARKER_66`. Цель — реальный технический код, описание берётся из той же записи основной матрицы. Псевдонимы учитываются при сопоставлении строк, что позволяет повторять импорт без дублей. Исходные справочники сохраняются; тексты сообщений не участвуют в подстановке. Конфликт с существующим значением или неизвестный целевой код останавливает импорт.

Номера столбцов справочников в config.json начинаются с единицы. Данные читаются со второй строки. Принимается единственное соответствие; одинаковые полные пары кода/описания допускаются. При чтении старой строки известный технический код может уточнить неоднозначное описание, если эта пара есть в справочнике. Если дано только неоднозначное описание, первый попавшийся код не выбирается. Входная строка с неоднозначным целевым описанием направляется на ручной разбор даже при явном коде: сохранённая формула INDEX/MATCH могла бы вычислить другой код после открытия результата.

Источником этих справочников является основная матрица. В шаблоне могут быть только «Каналы», «COMPLIANCE_STOP_LIST_CODES» и «Статусы Стоп Листа» — дополнительных листов не требуется. В сообщениях ошибок явно указывается основная матрица как источник справочника; имя шаблона указывает на обрабатываемую строку потребы.

Неполные пары кода/описания и непрочитанные формулы сохраняются в исходном справочнике, но не считаются готовыми соответствиями. Если такой записи соответствует запрошенный код или описание, импорт останавливается с указанием строки и ячеек. Если запрошенное значение не найдено, сообщение перечисляет до трёх неполных строк и номера настроенных столбцов для проверки структуры. Простые ссылки в справочниках раскрываются так же, как в шаблоне; кэш сложных формул не используется.

Образцовая строка основной матрицы — 2. Формулы переводятся на новую строку с относительным сдвигом; абсолютные ссылки не меняются. Константы образцовой строки, включая тексты, переключатели и отметки окружений, не копируются. Стиль копируется для всех столбцов.

Формулы с фиксированным абсолютным концом диапазона, например `$AK$3:$AK$12485`, остаются фиксированными. Программа не исправляет существующие `#ССЫЛКА!` и не оптимизирует формулы на целые столбцы.
