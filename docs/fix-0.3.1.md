# Версия 0.3.1: включение готовой ИФТ-версии в ПРОМ

Уточнён режим задачи ПРОМ. Новая строка в нём не создаётся и содержимое существующих записей не меняется.

1. Найти строку с IFT=1, у которой совпадают полный ключ, реакция, экранный заголовок и текст шаблона.
2. Поставить ей PROM=1. Её IFT, байпас и остальные поля сохранить.
3. Если есть прежняя ПРОМ-версия этого ключа, снять только её PROM. Её IFT, байпас и данные не трогать.

Если ИФТ-версия уже включена в ПРОМ, повторный запуск ничего не меняет. Если нужное содержимое уже есть в ПРОМ, а соответствующей ИФТ-версии нет, запись остаётся без изменений.

Несколько одинаково подходящих ИФТ-строк, несколько активных ПРОМ-версий, непрочитанные отметки, отсутствие или несовпадение готовой ИФТ-версии означают ручной разбор. При пропуске ни старая, ни новая отметка не меняется. Разные ИФТ-версии одного ключа можно различить по реакции, заголовку и тексту. Противоречащие друг другу шаблоны не переключают отметки.

Логика ИФТ из 0.3.0 сохранена: ИФТ-only строка редактируется, общая ИФТ/ПРОМ-строка разделяется с сохранением старого PROM. Пустой тип транзакции — нефинансовый. Байпас не импортируется.

Обновление: остановить программу Ctrl+C, заменить папку app и run.py из архива, сохранить свой config.json, запустить python3 run.py и обновить страницу. В комплекте есть искусственная демо-матрица. Полный цикл проверяйте сначала задачей ИФТ, затем задачей ПРОМ на полученном результате.

Проверено 106 автоматических тестов на Python 3.12 и 3.15. Новые проверки сравнивают все ячейки до/после включения в ПРОМ: допускаются только изменения PROM, число строк и прочие листы сохраняются. Проверены первое включение, замена прежней версии с сохранением IFT, разные и одинаковые ИФТ-версии, повторный запуск, несовпадение содержимого, байпас, конфликт шаблонов и HTTP-скачивание. Реальную рабочую матрицу необходимо проверить локально на копии.
