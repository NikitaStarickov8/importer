# Обновление 0.4.0

## Установка на рабочем Linux

1. Остановите программу в терминале: Ctrl+C.
2. Распакуйте архив обновления. Замените папку app и run.py в прежнем проекте. При желании обновите искусственный пример examples/01_matrix.xlsx.
3. Собственный config.json не заменяйте: aliases, расположение справочников и другие настройки сохраняются. Новый состав ключа применяется автоматически к старым конфигам.
4. Запустите python3 run.py и обновите страницу браузера (при необходимости Ctrl+Shift+R). Вверху должна быть версия 0.4.0.
5. Первый запуск сделайте на копии матрицы. Основные файлы программа не перезаписывает.

## Правила

Группа: CHANNEL_INDICATOR, SP_NAME, OPERATION_TYPE, RELATION_TYPE, CLIENT_TYPE, INSPECTED_PERSON, MATCH_NEGATIVE_CASE. Платформа SBOL_PRO_PLATFORM разделяет группы только для канала SBOL_PRO. Внутри группы одному BO_STEP_CODE_DESCRIPTION соответствует одна реакция, заголовок и текст.

Стопкод определяется по справочнику «Статусы Стоп Листа». Обычно код статуса в столбце 1, описание в 2, стопкод в 3. Для иной структуры задайте lookups.STOP_LIST_STATUS.step_code_col. Программа читает исходные значения и простые ссылки, не сохранённые результаты формул. Неоднозначное соответствие требует ручного разбора.

Обычное «Разрешено» из шаблона пропускается с причиной: отсутствие записи означает разрешение. Исключение — «В стоп-листе не найден / Разрешено». Другие резолюции (разрешение с сообщением и т. п.) не исключаются этим правилом. Старые разрешающие строки не удаляются и не деактивируются.

«Частичное совпадение» пропускается полностью до чтения остальных полей; только такие строки сами по себе не создают группу. Если в шаблоне есть обычное разрешение для полного совпадения, группа всё равно проверяется на обязательные записи.

Для каждой затронутой группы нужны две активные ИФТ-строки:

| Статус | Резолюция | Заголовок | Текст |
| --- | --- | --- | --- |
| В стоп-листе не найден | Разрешено | пусто | пусто |
| Технический запрет | Технический запрет | Сервис временно недоступен | Пожалуйста, попробуйте зайти через 5 минут или позже. |

Если строки нет в шаблоне, она формируется автоматически. Для автоматически сформированных записей MAX_AMOUNT пустой. Тип транзакции берётся из группы шаблона, при отсутствии — «Не финансовые операции». Если для одной группы даны разные типы транзакции, автоматически выбрать один нельзя: обязательные строки отправляются на ручной разбор.

Наличие обязательной строки проверяется по IFT=1, PROM=1 без ИФТ не заменяет её. Существующие правильные обязательные ИФТ-записи не дублируются и не переписываются, их тексты сохраняются. Неверная резолюция, несколько кандидатов, разные статусы одного стопкода или различие TRANSACTION_TYPE/MAX_AMOUNT требуют ручного разбора. Новая обязательная строка из шаблона сохраняет явно указанные в нём сообщения.

Обычные записи обновляются по прежним правилам: ИФТ-only на месте, общая ИФТ/ПРОМ-строка версионируется со снятием только IFT. ПРОМ-задача не создаёт строк и не переписывает содержимое: включает готовые ИФТ-версии и снимает прежние PROM. Для обязательных записей продвигается сохранённое содержимое ИФТ, даже если потребитель написал другой текст. Отсутствие обязательной ИФТ-версии в ПРОМ-задаче — ручной разбор.

Байпас по-прежнему игнорируется, существующий сохраняется; у новых строк пусто. Матрица массово не очищается и не дополняется по группам, не затронутым шаблонами.

## Отчёт

В браузере и скачиваемом .txt ровно три секции:

- Пропущено: обычное разрешение, частичное совпадение, уже имеющаяся обязательная строка, одинаковые данные, повтор, ручной разбор. Указаны причины и найденные строки матрицы.
- Добавлено: новые строки и ИФТ-версии, в том числе автоматические обязательные записи.
- Изменено: правки на месте и изменения отметок, включая снятие отметки со старой версии.

В каждом пункте есть физический номер строки Excel (если найден), источник и описание группы. Первый столбец CODE и сообщения о его пересчёте больше не выводятся. Автоматические записи помечены явно. Счётчик «Изменено» считает фактически изменённые строки, поэтому при переключении ПРОМ может показать две строки: старую и новую.

## Ограничения и проверки

Проверки выполняются на искусственных файлах, реальные рабочие матрицы не загружаются наружу. Старые тесты преобразования формул, справочников и версий запускаются отдельно с отключённой бизнес-политикой; тесты test_business_rules.py и test_policy_web.py проверяют новую политику по умолчанию, включая полный HTTP-путь.

Сохранение формул не означает их пересчёт средствами Python; результат нужно открыть в Р7/Excel. Сохраняется прежнее ограничение openpyxl: отдельные расширения условного форматирования и валидации Excel могут не сохраниться при записи. Проверяйте такие правила на копии; эта версия не меняет механизм сохранения книги.
