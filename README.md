# MatrixImporter

Локальная программа на Python для переноса заполненных Excel-шаблонов в основную матрицу проверок. Версия 0.4.3 — операция и подсистема определяются прежде всего по английским OPERATION_TYPE и SP_NAME. Если у одного кода несколько русских названий, используется первое по порядку строк справочника. Сохранены обязательные строки для каждой группы, исключение обычных разрешающих строк и частичного совпадения, отчёт «Пропущено / Добавлено / Изменено», подготовка ИФТ-версий и включение готовой ИФТ-строки в ПРОМ без копии. Байпас проверяется вручную, тип транзакции по умолчанию — «Не финансовые операции». Структура восстановлена по фотографиям, примеры искусственные.

## Быстрый запуск

С версии 0.4.3 служебные статусы NORMAL («В стоп-листе не найден») и TECH_ERROR («Технический запрет») встроены в программу и не проверяются по справочникам стоп-листа. Наличие соответствующих строк на справочных листах не требуется. У новых служебных строк коды, описания, нулевой приоритет, служебный STATUS_CODE и источник SL записываются явно, чтобы зависимые формулы не выдавали ошибки поиска. Остальные статусы проверяются как раньше; справочники и старые строки массово не меняются. Подробнее — docs/fix-0.4.3.md.

На Linux откройте терминал в папке проекта и выполните:

```sh
python3 run.py
```

Или `sh Запустить.sh`. На Mac можно дважды нажать **Запустить.command**. На Windows используйте **Запустить.bat**.

Нужен Python 3.10 или новее. Tkinter, pip, права администратора и установка системных пакетов для браузерного интерфейса не требуются. Библиотеки Excel уже включены в `vendor`.

Браузер откроется автоматически. Если этого не произошло, откройте адрес из терминала вручную — обычно **http://127.0.0.1:8765**. Если порт занят, программа выберет свободный и напечатает другой адрес. Терминал оставьте открытым.

На странице нажмите **Запустить демо**, дождитесь результата и нажмите **Скачать результат .xlsx**. Для ИФТ ожидаются **2 добавленные строки, 0 изменённых строк, 3 пропуска**. Существующий технический запрет сохраняется, обычное «Разрешено» не добавляется. Если среда ещё не выбрана, демо выбирает ИФТ.

Для обычного импорта выберите актуальную матрицу, добавьте шаблоны, обязательно укажите **ИФТ или ПРОМ** и нажмите **Импортировать**. Разные среды обрабатывайте отдельными запусками. Затем скачайте готовую матрицу. Папка скачивания определяется настройками браузера.

Программа запускает сервер только на `127.0.0.1`: браузер передаёт файлы процессу Python на этом же компьютере. Интернет, внешний сервер и загрузка рабочих файлов в облако не используются. Все стили и скрипты включены в проект.

Файлы для обработки временно копируются в системную временную папку. До остановки программы доступны несколько последних результатов. Чтобы завершить работу, нажмите **Ctrl+C** в терминале; при штатном завершении временные копии удаляются. Закрытие вкладки само по себе процесс Python не останавливает.

За один импорт можно выбрать до 500 шаблонов, до 256 МБ на файл и до 512 МБ суммарно.

После импорта откройте результат в Р7-Офис или Excel, дождитесь пересчёта формул и сохраните файл. Сам Python не пересчитывает формулы. Поиск записей выполняется по исходным значениям и справочникам, поэтому повторный импорт работает и до пересчёта.

## Что делает программа

- Находит технические заголовки столбцов: буквы столбцов могут меняться.
- Принимает технические коды и русские описания, проверяя соответствие по справочникам основной матрицы.
- Не требует дополнительных справочников в шаблоне: источником кодов является основная матрица. Посторонние неполные записи справочника не блокируют поиск; ошибка по нужному значению показывает лист, строку и ячейки.
- Читает простые ссылки шаблона (`=B3`, `=$B$3`, ссылки на другой лист и цепочки ссылок) без пересчёта и сохранённых результатов Excel. Общие поля шапки использует только для недостающих полей строки.
- Меняет только реакцию VALUE, заголовок TITLE_FOR_CLIENT и текст TEXT_FOR_CLIENT. Ключи существующей записи не переписываются.
- При задаче ИФТ создаёт новую версию общей ИФТ/ПРОМ-строки, снимая только IFT у старой. ИФТ-only запись обновляется на месте.
- При задаче ПРОМ ставит PROM=1 уже существующей готовой ИФТ-строке; с прежней ПРОМ-версии снимает только PROM. Новые строки и изменения содержимого в этом режиме не создаются.
- При добавлении копирует формулы и оформление образцовой строки, корректируя относительные ссылки.
- Расширяет диапазон Excel-таблицы, фильтра и подходящих диапазонов проверок/условного форматирования.
- Сохраняет отдельный новый `.xlsx`. Входные и существующие файлы не перезаписывает.
- Показывает три секции: пропущено (в том числе без изменений и ручной разбор), добавлено, изменено.

Если задаче ИФТ соответствуют несколько активных строк с одним ключом, запись пропускается. Для ПРОМ готовая ИФТ-версия определяется по полному ключу, реакции, заголовку и тексту; несколько полностью подходящих ИФТ-строк или несколько активных ПРОМ-строк требуют ручного разбора. Неоднозначное соответствие в справочнике также означает пропуск строки шаблона. При противоречии загруженных шаблонов для одного полного ключа пропускаются все варианты. Остальные строки обрабатываются, результат можно скачать. В блоке «На ручной разбор» показаны файл и строка шаблона, причина и подходящие строки матрицы.

Старые дубли и ошибки других записей не исправляются. Если старую строку нельзя разобрать, программа проверяет возможное пересечение с ключом шаблона. При возможном совпадении строка шаблона направляется на ручной разбор: неопределённость не считается отсутствием записи. Данные старой строки сохраняются. Неизвестный код в шаблоне, неверный формат, ошибочная настройка или небезопасная замена формулы по-прежнему останавливают пакет без сохранения.

## Итоговый отчёт по строкам

После обработки в браузере показаны три секции: «Пропущено», «Добавлено», «Изменено». У пропуска указана причина, включая совпадение данных без изменений, обычное разрешение, частичное совпадение, повтор или необходимость ручного разбора. У добавлений и изменений показаны номера строк Excel итоговой матрицы, описание группы, статус и источник в шаблоне. Автоматически сформированные обязательные записи помечены словом «Автоматически».

Изменения отметок у старой и новой версии показаны раздельно и со ссылками на связанные строки. Пропущенные и неизменённые записи не входят в список изменённых строк, но присутствуют в полном отчёте. Кнопка «Скачать отчёт .txt» сохраняет его отдельно от матрицы. Дополнительный лист в Excel не создаётся, история запусков на диск автоматически не записывается.

Номера — физические номера строк Excel в результате. Значения первого столбца и повторяющиеся сообщения о пересчёте в видимом отчёте больше не выводятся. Секция «Изменено» включает также снятие отметки со старой версии. Секция «Пропущено» включает и неизменённые записи; причины всегда указаны.

В CLI JSON добавлены affected_rows (изменённые строки), changes (действия с этими строками), outcomes (результат каждой строки шаблона) и change_report (полный текст отчёта). Настройки config.json менять не нужно.

## Как работает сопоставление

Для операции и подсистемы главные источники — английские OPERATION_TYPE и SP_NAME. Приоритет: явный код строки; технический код в прежнем столбце описания; код из шапки (D7/B7 для операции, D5/B5 для подсистемы); при отсутствии кода — точный поиск русского названия. Известный код определяет русское название из первой подходящей строки справочника: опечатка, другое русское название или ошибка формулы в шаблоне его не отменяют. Непрочитанную формулу кода в D7/D5 можно заменить ручным кодом B7/B5. Если у русского названия несколько разных кодов и английский код не указан, нужен ручной разбор. Неизвестный буквальный код по-прежнему блокирует импорт.

Если выбранное русское название разделяют несколько английских кодов, в новых строках соответствующая формула SP_NAME/OPERATION_TYPE заменяется исходным английским кодом. Иначе INDEX/MATCH мог бы вернуть другой код. При однозначном соответствии формулы кодов сохраняются. Русские названия новых строк записываются явно; существующие строки и справочники массово не переписываются. Остальные справочники сохраняют прежние проверки. Подробнее — docs/fix-0.4.2.md.

Ключ группы: `CHANNEL_INDICATOR + SP_NAME + OPERATION_TYPE + RELATION_TYPE + CLIENT_TYPE + INSPECTED_PERSON + MATCH_NEGATIVE_CASE`; для `SBOL_PRO` дополнительно учитывается `SBOL_PRO_PLATFORM`. Соответствие участника операции полю `RELATION_TYPE` подтверждено.

Внутри группы строки различаются по стопкоду `BO_STEP_CODE_DESCRIPTION`. Соответствие читается из справочника «Статусы Стоп Листа»: по умолчанию столбец 3, можно задать `lookups.STOP_LIST_STATUS.step_code_col`. Одному стопкоду соответствует одна реакция, заголовок и текст. Разные статусы с одним стопкодом, различия суммы или типа транзакции при совпавшем ключе требуют ручного разбора. Реакция и сообщения не входят в ключ.

Для каждой группы из шаблона требуются две активные ИФТ-записи: «В стоп-листе не найден / Разрешено» и «Технический запрет / Технический запрет». Если потребитель их не указал, программа создаёт недостающие строки в задаче ИФТ. У автоматического разрешения сумма, заголовок и текст пустые. У автоматического технического запрета сумма пустая, заголовок «Сервис временно недоступен», текст «Пожалуйста, попробуйте зайти через 5 минут или позже.». Уже существующие обязательные ИФТ-строки и их тексты не переписываются.

Обычное «Разрешено» для других статусов не импортируется: отсутствие строки означает разрешение. «Разрешено с сообщением» и прочие отдельные резолюции этим правилом не исключаются. Строки «Частичное совпадение» пропускаются полностью и не создают новые группы. Старая матрица массово не очищается. В задаче ПРОМ новые строки запрещены; обязательная запись тоже должна иметь готовую ИФТ-версию, её существующие тексты сохраняются.

При задаче ИФТ изменение ключа создаёт новую запись. Задача ПРОМ требует готовую ИФТ-версию с соответствующим ключом и содержимым. Строки, отсутствующие в шаблоне, остаются в матрице. Удаление по тексту задачи не автоматизировано.

Пустой TRANSACTION_TYPE_DESCRIPTION (при отсутствии явного кода) означает «Не финансовые операции» и в шаблоне, и при сопоставлении с матрицей. Для новых строк описание заполняется, код берётся из справочника «Типы транзакций» основной матрицы. «Финансовые операции» сохраняется отдельным типом и не смешивается с нефинансовыми. Код не зашит в программу. Если значения по умолчанию нет в справочнике, импорт остановится с объяснением. При необходимости точное название можно задать необязательным параметром transaction_type_default_description; старый config.json менять не требуется.

## Точечные соответствия названий

Если название в шаблоне отличается от основной матрицы, добавьте правило в секцию `aliases` файла `config.json`. Она находится на верхнем уровне, рядом с `lookups`:

```json
"aliases": {
  "STOP_LIST_STATUS": {
    "Флаг 66": "MARKER_66"
  }
}
```

Слева — название из шаблона, справа — существующий технический код из справочника основной матрицы. Например, по `MARKER_66` программа возьмёт описание `Маркер 66` и запишет его в `STOP_LIST_STATUS_DESCRIPTION`; формула технического столбца остаётся.

Другие правила можно дописывать в тот же объект через запятую. Названия секций полей совпадают с ключами `lookups` (`STOP_LIST_STATUS`, `CLIENT_TYPE` и т. д.). Правила относятся к конкретному полю; сообщения для клиента переносятся как обычный текст.

Регистр и лишние пробелы не влияют на поиск. Целевой код должен существовать в выбранной основной матрице; правило проверяется при его использовании. Существующие однозначные значения справочника нельзя переназначить на другой код. Цепочки псевдонимов не поддерживаются — справа указывается непосредственно код.

После изменения `config.json` достаточно запустить новый импорт. Для установки обновлённого Python-файла программу нужно перезапустить. Старые конфиги без секции `aliases` продолжают работать.

## Байпас и отметки окружений

Поле «Байпас» шаблона полностью игнорируется: произвольный текст и формулы в нём не влияют на импорт. Существующий VALUE_SWITCH сохраняется, включая пустое значение. У новых записей и новых версий он пустой — проверьте его вручную. Старая настройка bypass_values больше не применяется; bypass_target по-прежнему определяет, какой столбец оставлять пустым у новых строк.

| Среда задачи | Активная запись | Действие при изменении реакции/текста/заголовка |
| --- | --- | --- |
| ИФТ | IFT=1, PROM пусто/0 | Изменить на месте; отметки сохранить |
| ИФТ | IFT=1, PROM=1 | Снять только IFT со старой, добавить новую IFT=1 / PROM пусто |
| ИФТ | Нет активной ИФТ-записи | Добавить новую IFT=1 / PROM пусто |
| ПРОМ | Есть готовая ИФТ-строка, прежней ПРОМ-версии нет | Поставить PROM=1 существующей ИФТ-строке; IFT и данные сохранить |
| ПРОМ | Есть готовая ИФТ-строка и прежняя ПРОМ-версия | Снять только PROM со старой, поставить PROM=1 готовой ИФТ-строке |
| ПРОМ | Нет готовой ИФТ-версии либо есть неоднозначность | Пропустить запись с сообщением; отметки и данные не менять |

При задаче ИФТ совпадающее содержимое не создаёт новую версию. В ПРОМ включается существующая строка с IFT=1, совпадающая с шаблоном по ключу, VALUE, TITLE_FOR_CLIENT и TEXT_FOR_CLIENT. При повторном запуске уже включённая версия пропускается. Если ПРОМ уже содержит нужное содержимое, а подходящей ИФТ-строки нет, изменения не нужны. История с пустыми отметками не мешает поиску. Неоднозначные отметки требуют ручного разбора.

При создании ИФТ-версии копируются прочие поля и оформление старой, формулы переводятся на новую строку. CODE получает новую формулу/порядковое значение. У полностью новой ИФТ-записи остальные начальные значения берутся из new_row_defaults, однако IFT всегда 1, PROM и байпас пустые. В задаче ПРОМ никакие поля существующих строк, кроме PROM, не меняются: байпас, IFT, ключи, реакция и сообщения остаются как были.

Счётчик «Добавлено строк» включает новые ИФТ-версии; их количество указано отдельно. «Обновлено записей» — изменения ИФТ-only записей либо количество ИФТ-строк, включённых в ПРОМ. Для ПРОМ дополнительно показаны promoted (включено строк) и prom_deactivated (снято прежних отметок PROM). Всегда сохраняется отдельный файл результата.

## Примеры

- `examples/01_matrix.xlsx` — матрица из четырёх строк и листов-справочников.
- `examples/02_template_update.xlsx` — обновление текста, неизменившаяся запись и новая строка с байпасом «запрет».
- `examples/03_template_new_group.xlsx` — две строки другой операции/платформы.

Все значения в примерах искусственные. Демонстрационные формулы повторяют зависимости рабочей матрицы, но используют обычные построчные ссылки и ограниченные диапазоны. Точные хвосты некоторых формул на фотографиях не видны. При работе с настоящей матрицей программа берёт её собственные формулы, а не формулы демо-файла.

## Командная строка

Из папки проекта:

```sh
python3 run.py --environment IFT --matrix examples/01_matrix.xlsx --templates examples/02_template_update.xlsx examples/03_template_new_group.xlsx --output results/my_result.xlsx
```

Windows: замените `python3` на `py -3`. Параметр `--config путь.json` позволяет использовать отдельную настройку.

Дополнительные параметры браузерного запуска:

```sh
python3 run.py --no-browser
python3 run.py --port 8877
```

Старое окно оставлено как необязательный режим `python3 run.py --desktop`; только для него нужен Tkinter.

## Проверки

```sh
python3 -m unittest discover -s tests -v
python3 tests/benchmark.py --rows 50000
```

Тесты работают на временных копиях. Нагрузочная проверка создаёт и удаляет искусственную матрицу, не затрагивая рабочие файлы.

## Перед первым рабочим использованием

Структура восстановлена по фотографиям. На рабочем компьютере нужно проверить внутренний ключ строки, целевой столбец байпаса и перенос на нескольких известных потребах в копии матрицы. Для такого теста не требуется выносить рабочий файл из корпоративного контура.

Форматы `.xls`, `.xlsb`, макросы `.xlsm`, защищённые файлы и неизвестные вычисления в полях шаблона в этой версии не поддерживаются. Фиксированные абсолютные диапазоны и уже сломанные ссылки в рабочих формулах сохраняются как есть. Сохранность корпоративных расширений, IRM и всех особенностей Р7 по фотографиям проверить нельзя.

## Структура проекта

- `run.py` — запуск браузерной страницы или командной строки;
- `app/importer.py` — чтение, сопоставление и запись;
- `app/web.py` — локальный сервер;
- `app/web_assets` — HTML, CSS и JavaScript страницы;
- `app/gui.py` — необязательное старое окно Tkinter;
- `config.json` — ключи, справочники и байпас;
- `docs/mapping.md` — соответствия полей;
- `tests` — проверки;
- `vendor` — openpyxl 3.1.5 и et_xmlfile 2.0.0 с лицензиями.
